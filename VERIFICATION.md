# VulnAudit Verification Record

## Rubric

1. Exactly six named lab routes exist: `/login`, `/search`, `/user/<id>`, `/admin/debug`, `/static/`, `/transfer`.
2. The lab binds to `127.0.0.1:5000`; no `0.0.0.0` bind is present.
3. The scanner has six deterministic probe stages covering SQL injection, reflected XSS, IDOR, authentication, security misconfiguration, and CSRF.
4. Finding severity values are limited to Critical, High, Medium, Low, and Informational.
5. The PDF contains the seven required sections in PRD order.
6. JSON findings contain the required schema fields and response snippets are capped at 2 KB.
7. SQLite stores scans and findings; the dashboard computes new, fixed, and unchanged deltas.
8. README and DISCLAIMER contain the required educational/defensive-use statements.
9. Two unchanged scans produce identical finding sets and each completes below 30 seconds in the evidence harness.
10. Scanner target validation rejects non-local hosts by default.

## Evidence produced in the build session

- Static source checks passed for the six route set, localhost binding, six scanner probes, severity set, documentation banner, and target validation.
- `python -m pytest -q`: 2 passed, 2 skipped. The two skipped tests require Flask at runtime; Flask was not installed in the execution image and package installation was unavailable.
- A localhost-only HTTP evidence harness exercised the scanner twice. Each run produced 11 findings in 31–55 ms in the harness; both finding sets were identical.
- Two JSON reports and two PDFs were generated by the report pipeline.
- SQLite evidence contained 2 scan rows and 22 finding rows after the two runs.
- PDF text inspection confirmed the seven required sections in order and 11 risk statements.
- JSON schema validation passed with zero validation errors.
